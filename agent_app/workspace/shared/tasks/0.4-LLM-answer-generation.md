## 需求描述

ASR 识别到面试官说完一句话 → 自动调 DeepSeek → 流式推送 AI 回答 → 前端以对话气泡 + 打字机效果展示。

**核心变化（vs 0.3）：** 扔掉测试界面的 6 个调试组件，上真正的业务界面——面试官问题 + AI 回答成对展示的对话卡片流。

**触发规则：** 只对 system 轨（面试官）的 `is_final=true` 触发 LLM。mic 轨（用户）不触发。

## 接口契约（最终版）

复用现有 WebSocket `/ws/audio/stream:8010`，不新开连接。**LLM 默认开启，max_tokens 后端写死 300。config 帧可选（酱瓜已实现解析，前端不发 config 也能正常跑）。**

### 后端 → 前端（唯一新增消息类型）

```json
{
  "type": "llm_answer",
  "chunk": "增量文本片段",
  "chunk_index": 0,
  "is_final": false,
  "question_text": "面试官原话（仅 chunk_index=0 携带）",
  "timestamp": 1715000000000
}
```

**语义说明：**
- `chunk_index=0` + `is_final=false` → 前端创建新 AI 气泡 + 加载动画
- `chunk_index>0` + `is_final=false` → 前端追加文本（打字机效果）
- `is_final=true` → 前端标记回答完成，移除加载动画
- `question_text` 仅在 `chunk_index=0` 时携带，后续 chunk 不重复传

### 触发条件（后端）

```
source == "system" && is_final == true → 调 DeepSeek
source == "mic" → 仅记录，不触发 LLM
```

### 串行队列（后端消化）

面试官连问多句时，前一个 `is_final=true` 发出后才处理下一个触发。由后端维护队列，不影响契约。

## 技术决策记录

| 决策 | 结论 | 原因 |
|------|------|------|
| LLM 消息通道 | 复用 WS `:8010`，不新开 | 已有双向通道 |
| 消息类型 | 单类型 `llm_answer`（前端草案） | 比三类型简洁，语义通过 chunk_index + is_final 区分 |
| config 帧 | 可选（酱瓜已实现） | 最终契约砍了但实现了也不影响，前端不发也能跑 |
| max_tokens | 后端写死 300 | 够用，以后不够再加 config |
| 触发时机 | system 轨 `is_final=true` | 避免半句话触发 |
| 串行队列 | 后端消化 | 面试官连问场景 |
