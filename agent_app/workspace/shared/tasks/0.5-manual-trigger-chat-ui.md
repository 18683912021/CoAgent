## 需求描述

**砍掉 0.4 的自动触发。** 改为用户手动点击对话气泡 → 调 LLM 生成回答建议。

核心交互：对话流像微信聊天记录——面试官气泡左灰底、用户气泡右绿底，相邻两条同 source 间隔 >3 秒画分割线表示断句。点击任意气泡 → 底部弹出回答模式选择 → 调 LLM → AI 回答以新气泡插入该气泡下方。

**关键变化 vs 0.4：**
- ❌ 删掉自动触发（`source=="system" && is_final==true` 不再调 LLM）
- ✅ 手动点击触发：点哪个气泡就基于哪个气泡内容生成
- ✅ 面试官气泡和用户气泡都能点（用户气泡场景：假装重复问题）
- ✅ 三种回答模式：精简 ≤200 字 / 普通 ≤500 字 / 详细深入
- ✅ 不传上下文，仅传被点击气泡的文字内容
- ✅ System Prompt 升级：P8 角色 + ASR 文字纠偏 + 模式感知

## API 契约

### FE → BE：手动触发 LLM（新增）

```json
{
  "type": "llm_query",
  "text": "请介绍一下你的项目经验",
  "mode": "brief",
  "bubble_source": "system"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定 `"llm_query"` |
| `text` | string | 被点击气泡的完整文字内容 |
| `mode` | string | `"brief"` / `"normal"` / `"detailed"` |
| `bubble_source` | string | `"system"`（面试官气泡）/ `"mic"`（用户气泡），供后端日志用 |

### BE → FE：流式回答（与 0.4 兼容，微调）

```json
{
  "type": "llm_answer",
  "chunk": "增量文本片段",
  "chunk_index": 0,
  "is_final": false,
  "mode": "brief",
  "timestamp": 1715000000000
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定 `"llm_answer"` |
| `chunk` | string | 增量文本 |
| `chunk_index` | int | 从 0 开始递增 |
| `is_final` | bool | `true` 表示回答结束 |
| `mode` | string | 回显回答模式，前端可据此调整气泡样式 |
| `timestamp` | int | Unix 毫秒时间戳 |

> ⚠️ **变化：`question_text` 移除。** FE 已经知道点击的是哪个气泡，不需要回传。`mode` 新增，前端可据此给气泡加模式标签。

### 删除项

- ❌ 不再自动触发：`source=="system" && is_final==true` → 不调 LLM
- ❌ 不再需要 `question_text` 字段（FE 已持有上下文）
- ❌ config 帧仍然不加（LLM 默认开启，不变）

### 复用项

- ✅ WebSocket 连接不变：`/ws/audio/stream:8010`
- ✅ 音频推流 + ASR 转文字链路不变
- ✅ `transcription` 消息不变

## 回答模式规格

| 模式 | 前端标签 | System Prompt 指令 | max_tokens |
|------|----------|-------------------|:--:|
| `brief` | 精简 | "直击要点，不超过 200 字" | 200 |
| `normal` | 普通 | "完整回答，不超过 500 字" | 500 |
| `detailed` | 详细 | "深入展开，包含技术细节和项目经验" | 800 |

## System Prompt（V1）

```
你是拥有 10 年工作经验的 P8 级高级工程师。用户正在面试中，会把面试官的问题（语音识别转文字）发给你。

你需要：
1. 先判断语音识别文字是否有明显错误（如专有名词、技术术语被误识别），结合上下文修正后再回答
2. 根据用户选择的回答模式给出建议：
   - 精简模式：直击要点，不超过 200 字
   - 普通模式：完整回答，不超过 500 字
   - 详细模式：深入展开，包含技术细节和项目经验
3. 口语化表达，像在真正面试中说话一样
4. 不编造经历，不输出 markdown 格式
5. 直接给出回答建议，不加前缀如"你可以这样说"或"建议回答"
```

## FE 任务

### 0.5.1-FE：对话气泡界面

- 面试官气泡：左对齐，灰底（#F0F0F0），左侧带「🎙️ 面试官」标签
- 用户气泡：右对齐，绿底（#95EC69），右侧带「👤 我」标签
- AI 回答气泡：左对齐，蓝底虚线边框（#D6EAF8），左侧带「🤖 AI 建议」+ 模式标签
- 气泡内显示文字 + 时间戳（HH:MM:SS）
- 3 秒断句规则：相邻两条同 source 的 transcription 时间戳间隔 >3 秒 → 渲染分割线（灰色横线 + 「3s」标注）
- 自动滚动到最新消息

### 0.5.2-FE：手动点击触发

- 点击面试官气泡或用户气泡 → 底部弹出模式选择面板
- 面板三个按钮：「精简」「普通」「详细」，点击后发送 `llm_query`
- 发送后：在被点击气泡下方插入一个新 AI 气泡，显示加载动画
- 收到 `llm_answer` chunk → 打字机追加；`is_final=true` → 移除加载动画
- 加载中可继续点击其他气泡（多个 AI 回答可并行生成）

### 0.5.3-FE：回答模式选择器

- 底部面板：三个按钮水平排列，当前选中高亮
- 面板可从底部上滑弹出（Sheet/BottomSheet），点击气泡时自动弹出
- 面板外点击或滑动可关闭

### 0.5.4-FE：清理 0.4 自动触发残留

- 对话界面不再预期"自动冒 AI 气泡"
- `llm_answer` 只在用户手动触发 `llm_query` 后才消费
- 如收到非预期的 `llm_answer`（无对应请求），静默丢弃 + 日志 warning

**验收标准：**
- [ ] 对话气泡界面：面试官左灰 / 用户右绿 / AI 左蓝虚线
- [ ] 3 秒断句分割线正确渲染
- [ ] 点击气泡 → 底部弹模式选择 → 发 `llm_query`
- [ ] 打字机效果流畅，AI 气泡正确插入到被点击气泡下方
- [ ] 并行生成不冲突（点多个气泡各自独立）
- [ ] 四态：正常流 / 边界（快速连点）/ 异常（LLM 失败红色提示）/ 空态（「等待面试官提问...」）

## 技术决策记录

| 决策 | 结论 | 原因 |
|------|------|------|
| 触发方式 | 手动点击，砍掉自动触发 | boss 拍板：用户自己判断需要帮助的时刻 |
| 上下文 | 不传上下文，仅单气泡文字 | boss 拍板：面试问题独立，不需要对话历史 |
| 可点击范围 | 面试官气泡 + 用户气泡均可 | 用户气泡场景：假装重复问题 |
| 回答模式 | brief(≤200) / normal(≤500) / detailed(≤800) | boss 拍板，三段式控制 |
| 模式选择 UI | 底部上滑面板，三按钮 | 点击气泡后弹出，自然交互 |
| 并行生成 | 支持（不互斥） | 用户可能快速点击多个问题 |
| 非预期 llm_answer | 静默丢弃 + 日志 warning | 防御自动触发残留 |
