# AI Interview Copilot — 研发阶段规划

> **核心原则：阶段零不过，不动阶段一。每个阶段有明确验收标准，达标再推进。**
>
> **前端模板：** `workspace/fe/rn-app-shell` 是已配置 Expo 云打包的 RN 壳子，作为模板保留不动。后续所有前端业务开发，从模板复制新项目开始写代码。
>
> **产品形态：纯 App。** 用户用手机进行线上面试（腾讯会议/飞书/视频面试）时，同一台手机同时运行 Copilot，从系统内部音频流采集面试官声音 → ASR 识别 → LLM 实时生成回答 + 自动记录面试内容。一个设备搞定全部，不做电脑版。
> 
> **⚠️ 关键澄清：** 不是麦克风"偷听"环境音。音频来源是系统内部音频流（音频回采/屏幕录制音频通道），而非物理麦克风收音。手机同时跑视频面试 App 和 Copilot，Copilot 从系统层捕获面试官的声音。

---

## 阶段零 · 技术原型验证

**需求描述：** 用户在手机上进行线上面试（腾讯会议/飞书/视频面试）时，同一台手机同时运行 Copilot App → 系统内部音频流采集面试官声音 → 实时转文字 → LLM 生成答案并展示在屏幕上。纯技术验证，不做登录、知识库、UI 美化、延时优化。

### 0.1 — 技术选型

> 状态：LLM/ASR 已定，PoC 骨架完成，剩余 MediaProjection 权限流程 + 真机验证

#### 🎯 选型结论（已确认）

| 组件 | 选型 | 定论 |
|------|------|------|
| **LLM** | **DeepSeek**（V4-Pro/V4-Flash） | boss 拍板。兼容 OpenAI ChatCompletions 接口，`/v1/chat/completions` 直调。旧模型名 2026.7 停用自动指向 V4-Flash。 |
| **ASR + 说话人分离** | **腾讯云实时说话人分离** | 唯一一家把实时 ASR + 说话人分离做成一个干净 WebSocket API 的厂商。`wss://` 一个连接同时返回识别文本 + `speaker_id`（0/1），PCM 16kHz / 40ms 1280字节发包。voice_id 每连接必换 UUID。 |

#### 📊 ASR 竞对核查结论（2026.7 已验证）

| 维度 | **腾讯云（已选）** | 讯飞 | 阿里云 | 火山引擎 |
|------|:--:|:--:|:--:|:--:|
| 实时 WebSocket | ✅ | ✅ | ✅ | ✅ |
| 实时说话人分离 | ✅ 独立 API | ✅ 大模型版（rtasr_llm）| ⚠️ Fun-ASR-Realtime 有，字段未明确 | ❌ 录音文件级 |
| 一个 WS 出 speaker_id | ✅ | ⚠️ 两套体系（标准版不带、大模型版才带）| ⚠️ 文档不透明 | ❌ |
| 中文准确率 | 97%（微信同款）| 老牌强 | Fun-ASR 不错 | 大模型版新 |

> **选腾讯云的核心逻辑：** 不是"唯一一家"，而是"唯一一家把实时说话人分离做成一个干净 WebSocket API 的"。讯飞要切大模型版（两套体系）、阿里云 API 字段不透明、火山直接没有——小团队优先选接入体验和文档清晰度。

#### ⚠️ speaker_id 产品方案（已确认）

腾讯云只返回匿名 `speaker_id`（0/1），不标记谁是面试官。产品侧方案：

- **面试开始前弹半屏面板**：「请确认你的身份」→ [我是面试官] [我是候选人]
- 用户选「我是候选人」→ 后端建映射：另一个 speaker_id = 面试官
- 如果返回的 speaker_id 和用户标记对不上，前端在用户第一句话旁标「👤 你」，支持手动纠正

### 0.2 — 系统音频流采集（产品根基）

> 状态：PoC 骨架完成，待真机验证

#### 需求描述
在手机端通过系统内部音频流实时采集线上面试的对话音频，推流到后端。**核心场景**：用户用同一台手机同时运行视频面试App（腾讯会议/飞书等）和 Copilot，Copilot 从系统层捕获面试官的声音。验证线上视频面试场景下音频采集的可行性和稳定性。

#### FE 任务清单
- [ ] 0.2.1-FE：系统音频权限与采集——基于 0.1 选型结论，实现系统音频回采（Audio Loopback / 屏幕录制音频通道），获取系统内部音频流并编码为 PCM 输出
- [ ] 0.2.2-FE：音频采集 PoC——最小可用版本：打开 Copilot → 开启系统音频采集 → 推流到后端。验证：① 与视频面试App同时运行时能否正常捕获音频 ② 手机息屏/切换 App 时采集是否中断
- [ ] 0.2.3-FE：音频格式配置——确认采样率（16kHz）、位深（16bit）、单声道，与后端对齐格式

#### BE 任务清单
- [ ] 0.2.4-BE：接收前端音频流，验证格式（16kHz/16bit 单声道）、采样率、声道数是否满足 ASR 要求
- [ ] 0.2.5-BE：系统音频采集效果验证——模拟线上视频面试场景（手机同时运行视频会议 + Copilot），确认面试官声音可被清晰捕获

#### 验收标准
- [ ] 手机端能通过系统音频流实时采集线上面试音频并推流到后端
- [ ] 面试官声音能被清晰采集（系统内部音频通道，无物理距离概念）
- [ ] PCM 流格式经后端验证符合 ASR 要求
- [ ] 确认息屏/切换 App 场景下的采集行为（允许暂时中断，但需明确限制条件）
