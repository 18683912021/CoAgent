# AI Interview Copilot — 研发阶段规划

> **核心原则：阶段零不过，不动阶段一。每个阶段有明确验收标准，达标再推进。**
>
> **前端模板：** `workspace/fe/rn-app-shell` 是已配置 Expo 云打包的 RN 壳子，作为模板保留不动。后续所有前端业务开发，从模板复制新项目开始写代码。
>
> **产品形态：纯 App。** 手机麦克风同时采集面试官和用户自己的声音 → 实时区分说话人 → ASR 双通道识别 → LLM 生成回答 + 自动记录面试内容。一个设备搞定全部，不做电脑版。

---

## 阶段零 · 技术原型验证

**需求描述：** 手机上打开 App 放在旁边，面试官提问、用户回答 → 手机麦克风双向采集 → 自动区分说话人 → 屏幕上展示面试官问题文字 + AI 答案。纯技术验证，不做登录、知识库、UI 美化、延时优化。

---

> 状态：进行中

#### 需求描述
确定 ASR/LLM 供应商，搭建开发环境，确认前端麦克风双向音频采集 + 说话人分离方案的可行性。

#### FE 任务清单
- [ ] 0.1.1-FE：评估 RN 麦克风音频采集方案——Expo Audio / expo-av 等，确认能否实时采集麦克风音频流并推送到后端。**关键：需要同时采集面试官和用户双方声音（同一音轨即可，说话人分离由后端处理）**，输出可行性结论
- [x] 0.1.2-FE：✅ 技术栈已确定：React Native + Expo，壳子模板 `rn-app-shell` 已跑通云打包

#### BE 任务清单
- [ ] 0.1.3-BE：ASR 供应商选型——对比讯飞、Deepgram、Azure Speech、阿里云。除常规指标（中文准确率、实时流支持、价格、SDK 成熟度）外，**必须评估说话人分离（Speaker Diarization）能力**——能否自动区分「面试官」和「应聘者」两个说话人。输出选型报告
- [ ] 0.1.4-BE：LLM 供应商选型——对比 GPT-4o、Claude、DeepSeek、通义千问（回答质量、流式延迟、API 稳定性、成本），输出选型报告

#### 开发环境
- [ ] 0.1.5-INFRA：代码仓库、CI/CD 骨架、本地调试环境跑通。前端从 `rn-app-shell` 复制原型项目

#### 验收标准
- [ ] ASR 供应商选型报告完成，有明确推荐（含说话人分离能力评估）
- [ ] LLM 供应商选型报告完成，有明确推荐
- [ ] 前后端本地开发环境均可运行
- [ ] RN 麦克风音频采集方案有明确可行性结论

### 0.2 — 麦克风双向音频采集（产品根基）

> 状态：待开发

#### 需求描述
在手机端通过麦克风实时采集面试对话音频，推流到后端。**核心场景**：面试官提问 + 用户回答，两人的声音都会被麦克风收到，后端负责区分谁在说话。验证真实面试场景下双向收音效果（距离、噪音、两人音量差异）。

#### FE 任务清单
- [ ] 0.2.1-FE：麦克风权限与音频采集——基于 0.1 选型结论，实现麦克风权限申请、实时音频流采集、PCM 编码，输出 PCM 流
- [ ] 0.2.2-FE：音频采集 PoC——最小可用版本：点击开始监听 → 麦克风采集（面试官+用户双方声音）→ 推流到后端。验证手机息屏/切换 App 时采集是否中断
- [ ] 0.2.3-FE：音频格式配置——确认采样率（16kHz）、位深（16bit）、单声道，与后端对齐格式

#### BE 任务清单
- [ ] 0.2.4-BE：接收前端音频流，验证格式（16kHz/16bit 单声道）、采样率、声道数是否满足 ASR 要求
- [ ] 0.2.5-BE：双向收音效果验证——模拟真实面试场景（两人对话，距离手机 0.5-1.5 米），确认双方音量均可识别

#### 验收标准
- [ ] 手机端能通过麦克风实时采集音频并推流到后端
- [ ] 面试官和用户双方声音均能被清晰采集（1.5 米范围内正常音量）
- [ ] PCM 流格式经后端验证符合 ASR 要求
- [ ] 确认息屏/切换 App 场景下的采集行为（允许暂时中断，但需明确限制条件）

#### FE 任务清单
- [ ] 0.3.1-FE：识别结果展示——WebSocket/SSE 接收后端推送的识别文字，区分展示「面试官」和「我」两个标签

#### BE 任务清单
- [ ] 0.3.2-BE：ASR SDK 接入——接入选定供应商的实时流式识别 SDK，跑通音频流输入到识别结果输出
- [ ] 0.3.3-BE：说话人分离集成——启用 Speaker Diarization，验证能否将音频流中的两人正确标记为 Speaker A / Speaker B
- [ ] 0.3.4-BE：中文识别基线测试——准备技术面试常见术语+中英混合+二人对话样本，测准确率，记录错误 case

#### 验收标准
- [ ] 实时流式识别跑通，音频流送入后 2 秒内出文字
- [ ] 说话人分离能正确区分面试官和用户（两人交替说话的典型场景，区分准确率 ≥ 85%）

- [ ] 前端能实时展示识别文字，且正确标记说话人

ASR 识别出面试官问题 → LLM → 流式输出面试回答。设计基础 System Prompt，测 10 道典型面试题的回答可用性。**注意：只对面试官说的话生成回答，用户自己的话不需要 AI 回答。**

#### FE 任务清单

#### BE 任务清单

- [ ] 0.4.3-BE：回答生成联调——面试官识别文字 → LLM → 流式输出。测 10 道典型面试题，记录回答可用性
- [ ] 0.4.4-BE：说话人过滤——确保只对 Speaker A（面试官）的识别结果触发 LLM 回答，用户自己的话不触发

#### 验收标准
- [ ] 流式回答生成跑通，首字延迟可接受
- [ ] 10 道测试题中 ≥ 8 道回答可用（不编造、口语化、切题）
- [ ] 用户自己说的话不会触发 AI 回答

- [ ] 0.5.2-FE：实景测试——真实面试模拟：一人扮演面试官提问、一人扮演用户回答，手机放桌上采集。验证：① 面试官问题正确识别并触发 AI 回答 ② 用户回答被正确记录但**不**触发 AI 回答

- [ ] ASR + 说话人分离能正确区分两人并分别识别
- [ ] LLM 只对面试官问题生成回答，用户说话不触发
- [ ] 整场面试对话被自动记录下来
- [ ] 线下面试场景全链路跑通
- [ ] 延迟不考核
