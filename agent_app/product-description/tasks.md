### 0.2 — 系统音频捕获（产品根基）

> 状态：待开发

#### 需求描述
在电脑端无感知捕获系统播放音频（面试官说话的声音），不依赖麦克风录扬声器外放。这是整个产品的根基——收不到面试官声音，后面全白做。

#### FE 任务清单
- [ ] 0.2.1-FE：Mac 音频回路调研——BlackHole / Soundflower / ScreenCaptureKit，验证能否无感知捕获系统音频
- [ ] 0.2.2-FE：Windows 音频回路调研——WASAPI Loopback / VB-Cable / Stereo Mix，验证系统音频采集方案
- [ ] 0.2.3-FE：音频采集 PoC——基于调研结果实现最小可用版本：启动监听 → 捕获系统音频 → 输出 PCM 流

#### BE 任务清单
- [ ] 0.2.4-BE：接收前端音频流，验证格式（16kHz/16bit 单声道）、采样率、声道数是否满足 ASR 要求

#### 验收标准
- [ ] Mac 端能捕获系统音频，不依赖麦克风
- [ ] Windows 端能捕获系统音频，不依赖麦克风
- [ ] PCM 流格式经后端验证符合 ASR 要求

## 阶段三 · V2 数据壁垒（护城河）

**需求描述：** 积累面试数据形成行业壁垒——面试题库、公司面经、岗位高频题、AI 预测追问方向。

---

### 3.1 — 面试题库

> 状态：待开发

#### 需求描述
系统化积累面试题，按公司/岗位/技术栈分类，标注难度和频次。

#### FE 任务清单
- [ ] 3.1.1-FE：题库浏览页面——按公司/岗位/技术栈筛选、搜索、查看题目详情与参考答案
- [ ] 3.1.2-FE：题目贡献——用户可提交遇到的面试题，标注公司+岗位

#### BE 任务清单
- [ ] 3.1.3-BE：题目结构化存储——题目分类体系（公司/岗位/技术栈/难度/题型）、去重算法
- [ ] 3.1.4-BE：题目统计分析——高频题排行、公司偏好分析、岗位核心考点

#### 验收标准
- [ ] 题库至少积累 100+ 经过审核的题目
- [ ] 按公司筛选时题目相关性 ≥ 80%

---

### 3.2 — 公司面试情报

> 状态：待开发

#### 需求描述
聚合特定公司的面试流程、风格偏好、常见考点、薪资范围。

#### FE 任务清单
- [ ] 3.2.1-FE：公司情报页面——面试流程可视化、常见考点标签云、面经时间线

#### BE 任务清单
- [ ] 3.2.2-BE：情报聚合——从用户面经中提取结构化情报，聚合到公司维度
- [ ] 3.2.3-BE：情报推荐——用户输入目标公司+岗位，自动推荐备考方向和重点

#### 验收标准
- [ ] 覆盖 ≥ 20 家公司的面试情报
- [ ] 情报与实际面试体验一致性 ≥ 70%

---

### 3.3 — AI 追问预测

> 状态：待开发

#### 需求描述
基于当前问题 + 岗位要求 + 历史面经，预测面试官可能的追问方向，提前准备。

#### FE 任务清单
- [ ] 3.3.1-FE：追问预测展示——当前问题下方展示 2-3 个可能的追问方向 + 简要提示

#### BE 任务清单
- [ ] 3.3.2-BE：追问预测模型——基于题目关联图谱 + 面试官常见追问模式，实时生成预测
- [ ] 3.3.3-BE：追问覆盖率评估——对比预测 vs 实际追问，持续优化模型

#### 验收标准
- [ ] 实际发生的追问在预测 Top 3 中的命中率 ≥ 50%
- [ ] 预测延迟 < 1 秒

---

### 3.4 — 面试表现分析

> 状态：待开发

#### 需求描述
面试结束后自动生成分析报告：回答质量评估、薄弱知识点、改进建议。

#### FE 任务清单
- [ ] 3.4.1-FE：分析报告页面——得分雷达图、薄弱点列表、改进建议、对比历史趋势

#### BE 任务清单
- [ ] 3.4.2-BE：回答质量评估——LLM 对每轮回答评分（内容完整性/逻辑性/匹配度），输出薄弱点
- [ ] 3.4.3-BE：趋势分析——多场面试对比，追踪进步曲线

#### 验收标准
- [ ] 面试结束后 1 分钟内生成分析报告
- [ ] 薄弱点识别与实际面试结果一致性 ≥ 60%
